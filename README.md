# Linux для DevOps

Исходники учебных опытов BoostMentor: Bash, процессы и файловые дескрипторы,
systemd, CPU и ожидание диска, логи nginx. Это отдельный репозиторий Linux-выпуска;
исходники Kubernetes-видео остаются в своём репозитории.

## Получить исходники

На учебной Linux VM, под обычным пользователем:

```bash
git clone --depth 1 https://github.com/boost-mentor/linux-for-devops.git ~/linux-video-sources
```

Перед повторной записью обновить **уже существующую** копию:

```bash
git -C ~/linux-video-sources status --short
```

Если вывод пустой, свои правки отсутствуют:

```bash
git -C ~/linux-video-sources pull --ff-only
```

```bash
git -C ~/linux-video-sources rev-parse --short HEAD
```

Если есть правки или Git отказался обновлять копию, остановитесь и разберите
причину. Не сбрасывайте свои изменения ради примера. Обновление исходников не
очищает результаты предыдущих опытов. В сценарии VM используется пользователь
`student`, поэтому там тот же путь записан как `/home/student/linux-video-sources`.

## Что открыть перед запуском

Все исходники находятся в `examples/`. Сначала прочитайте нужный файл, затем
собирайте или запускайте его. Автоматического запуска всего выпуска здесь нет.

| Файл | Для чего нужен |
|---|---|
| `status-demo.sh` | `set -e`: остановка после `false` в обычной последовательности |
| `unset-demo.sh` | `set -u`: ошибка при обращении к незаданной переменной |
| `pipe-demo.sh` | Поведение конвейера без `pipefail` и с ним |
| `strict-demo.sh` | Совместное действие `set -euo pipefail` |
| `hold-file.go` | Открыть файл, увидеть PID/FD, закрыть FD отдельно от завершения процесса |
| `linux-video.service` | Пользовательская служба systemd: наблюдение за `notes.txt` |
| `cpu-burn.go` | Четыре вычислительных работника, остановка сигналом или через 120 секунд |
| `disk-delay.sh` | Ограниченный опыт с искусственной задержкой чтения; только на подготовленной VM |
| `nginx.conf` | Отдельный локальный nginx с собственными логами |
| `logrotate.conf` | Ротация учебного access.log и штатное переоткрытие логов nginx |

## Среда и границы безопасности

- Отдельная одноразовая Linux VM с systemd; ориентир стенда — Ubuntu 24.04,
  4 логических CPU, 8 GiB RAM. Не production и не рабочий Mac.
- Инструменты: Bash, Git, Go **1.19 или новее**, strace, htop, procps,
  util-linux, sysstat, lsof, nginx, logrotate, curl, fio и device-mapper.
  Установка и наличие прав проверяются **до** записи, не скрытой командой из примера.
- Работайте обычной учётной записью. `sudo` требуется только для специально
  подготовленного дискового опыта; не запускайте весь комплект от root.
- Результаты опытов держите отдельно от исходников. `hold-file.go` создаёт и
  **обрезает** `held.log` в текущем каталоге. Поэтому запускайте его только в новой
  учебной папке, где нет нужного файла с таким именем.
- `linux-video.service` читает `%h/linux-video/notes.txt`. Этот файл создаётся и
  объясняется в начале выпуска. Unit не создаёт его за вас.
- nginx использует только `127.0.0.1:18085`, собственный prefix
  `/tmp/linux-video-nginx/` и папки `logs`/`temp`. Конфиги копируются туда явно,
  не в `/etc/nginx` и не в `/etc/logrotate.d`. Занятый порт — повод остановиться,
  а не завершать чужой nginx.
- `truncate`, перенаправление `>` и `rm` уничтожают данные или имена. Применяйте
  их **только к учебному логу**. В эксплуатации сначала решают, нужно ли сохранить
  историю. Для nginx используется `reopen`; перезапуск сервера ради лога не нужен.
- `disk-delay.sh` специально откажется запускаться вне подготовленного стенда:
  он проверяет маркер `/etc/linux-video-lab` со значением
  `linux-video-20261015`. Не снимайте эту защиту на рабочей машине. Администратор
  отдельной учебной VM должен заранее проверить её назначение и подготовку.
  Опыт выделяет файл 256 MiB, создаёт read-only loop/dm-устройство, читает его
  90 секунд, затем пытается штатно отсоединить. Исходный файл остаётся для проверки.
  Наличие прошлого каталога или устройства останавливает повторный запуск;
  автоматического удаления старого опыта нет.

## Особенности примеров

Go-файлы — **две отдельные программы**, поэтому собирайте конкретный файл,
не `go build .`. Например, из новой учебной папки:

```bash
go build -o hold-file ~/linux-video-sources/examples/hold-file.go
```

```bash
./hold-file
```

Первый Enter закрывает файл, второй завершает программу. Число FD берите из
вывода: оно не обязано равняться трём. Наблюдение `/proc/PID/fd` и strace выполняется
на Linux; простая сборка на другой ОС не подтверждает этот опыт.

Bash-примеры намеренно завершаются с ошибкой. Для `status-demo.sh`,
`unset-demo.sh`, `pipe-demo.sh` и `strict-demo.sh` строка `after` не должна появиться.
Это проверка поведения, а не поломка пакета. `-e` имеет исключения для проверок и
условных конструкций; сочетание опций не откатывает уже выполненные изменения.

У nginx ротация и `reopen` выполняются асинхронно. После них проверяют новый
запрос и новую запись в логе, а не только успешное завершение управляющей команды.
`logrotate.conf` — политика, не расписание: регулярный запуск обеспечивают
отдельно. `copytruncate` в этой политике не нужен — nginx умеет переоткрывать лог.
